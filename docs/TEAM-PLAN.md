# План для команды из 3 человек

Общий лимит: 5 часов, включая репетицию и сборку сдачи. Назначьте конкретные имена на роли A, B и C в начале работы.

| Участник | Основная ответственность | Файлы | На защите |
|---|---|---|---|
| A: интерфейс и демонстрация | Каталог, конструктор, кабинеты бизнеса и команды, стили | `static/` | Управляет браузером и показывает переходы |
| B: сервер и данные | SQLite, рейтинг, публикация, отклики, ручной выбор, этапы | `server.py`, кроме AI-функций | Объясняет рейтинг, данные и ограничения |
| C: AI и качество | AI-контракт, вопросы, тесты, README, презентация | AI-функции в `server.py`, `tests/`, `docs/` | Объясняет проблему и AI, завершает защиту |

B и C редактируют разные функции в одном серверном файле. Перед параллельными правками договоритесь о границах: C отвечает за `AI_PROMPT`, `QUESTIONS`, `ai_questions`, `validate_ai_result`; B — за остальное. Интеграция небольшими изменениями каждые 30–40 минут.

## График на 5 часов

| Время | Участник A | Участник B | Участник C | Общая контрольная точка |
|---|---|---|---|---|
| 00:00–00:30 | Каркас экранов | Схема данных и API | Сценарий и AI-контракт | Согласованы поля и статусы |
| 00:30–01:40 | Черновик, вопросы, редактор | Сохранение карточки и проверка ввода | Вопросы по пропускам, проверка AI-ответов | Черновик становится карточкой |
| 01:40–02:45 | Рейтинг и каталог | Формула, пересчёт, сортировка | Границы уровней и тестовые данные | Рост рейтинга меняет позицию |
| 02:45–03:45 | Форма отклика и кабинет | Отклики, ручные решения, этапы | Проверка полного сценария | Команда откликается, бизнес выбирает |
| 03:45–04:30 | Исправления интерфейса | Ошибки и сохранение данных | Тесты и README | Сценарий проходит без сбоев |
| 04:30–05:00 | Прогон в браузере | Проверка запуска из архива | Презентация и тайминг | Сдача и демонстрация до 5 минут |

## Как использовать подготовленный MVP

Реализация основных функций уже есть. На оставшееся время распределите работу так: A проверяет пользовательские экраны и текст, B запускает тесты и изучает формулу, C репетирует объяснение AI-заглушки и сверяет сдачу с правилами организаторов. Затем все трое проходят `DEMO.md` с таймером.

Если доступен реальный AI API, C может подключить его через описанный контракт, не меняя расчёт рейтинга и ручные решения. Наличие сети и ключа нужно проверить заранее. До стабильного прохождения основного сценария не добавляйте чат, регистрацию, сложные рекомендации и интеграции.

## Перед сдачей

- У каждого есть исходники и понятная команда запуска.
- На демонстрационном компьютере создана отдельная база для репетиции.
- A умеет переключать роли, B может объяснить каждый балл, C честно описывает локальную заглушку.
- README содержит инструкцию запуска, ограничения и тестовые сценарии.
- Архив открывается на другом компьютере с Python 3.10+.
- Организационные правила и формат загрузки проверены командой отдельно.
