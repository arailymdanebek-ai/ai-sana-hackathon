# AI Sana Challenge Hub

**Платформа, которая помогает бизнесу подготовить понятную задачу и найти студенческую команду через открытый каталог.**

MVP для трека «Образование», кейс МНВО — AI Sana. Приложение проводит задачу через полный сценарий: черновик, уточнение, подтверждение карточки, рейтинг готовности, публикация, отклик команды, ручной выбор бизнеса и подтверждение результата этапа.

> **Текущая версия:** локальное веб-приложение с сохранением в SQLite. AI-функция работает как явно обозначенная детерминированная заглушка, допустимая по ТЗ. Внешняя языковая модель и настоящая авторизация не подключены.

## Проблема и решение

Бизнес часто формулирует потребность в одном предложении: «Хотим лучше планировать закупки». Студентам неизвестно, какие данные доступны, кто будет пользоваться решением, какой результат ожидается и как его проверят.

Challenge Hub помогает дополнить описание вопросами, собрать редактируемую карточку и увидеть недостающие сведения. Рейтинг делает подготовку задачи заметной: чем больше подтверждённых сведений, тем выше позиция в каталоге. Команды самостоятельно откликаются, а бизнес принимает решение о сотрудничестве.

Главная геймификация направлена на **качество описания задачи бизнесом**. Баллы команды за подтверждённые этапы считаются отдельно.

## Запуск

### Требования

- Python **3.10+** со стандартным модулем `sqlite3`.
- Современный браузер с включённым JavaScript.
- Git для клонирования или скачанный ZIP проекта.

Устанавливать Python-пакеты, Node.js, базу данных отдельным сервисом или API-ключ не требуется. Интернет нужен для получения исходников; само приложение работает локально без внешних запросов. Внешние ссылки на прототипы открываются отдельно.

### macOS и Linux

Пока pull request №1 не объединён, клонируйте ветку с реализацией:

```bash
git clone --branch codex/ai-sana-mvp https://github.com/arailymdanebek-ai/ai-sana-hackathon.git
cd ai-sana-hackathon
python3 --version
python3 server.py
```

### Windows, PowerShell

```powershell
git clone --branch codex/ai-sana-mvp https://github.com/arailymdanebek-ai/ai-sana-hackathon.git
cd ai-sana-hackathon
py --version
py server.py
```

Если Python установлен без команды `py`, используйте `python server.py`.

### Запуск из ZIP

1. Распакуйте архив полностью.
2. Откройте терминал в папке, где находится `server.py`.
3. Выполните `python3 server.py` или `py server.py`.

При успешном запуске терминал покажет:

```text
AI Sana Hub → http://127.0.0.1:8765
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Терминал должен оставаться открытым. Для остановки нажмите **Ctrl+C**. Открывать `static/index.html` напрямую через `file://` не нужно: интерфейс обращается к Python API.

### Параметры запуска

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--port` | `8765` | Порт HTTP-сервера |
| `--host` | `127.0.0.1` | Адрес, на котором сервер принимает соединения |
| `SANA_DB` | `data/hub.sqlite3` рядом с `server.py` | Путь к SQLite-файлу |

Другой порт:

```bash
python3 server.py --port 8766
```

После этого открывайте `http://127.0.0.1:8766`. Все примеры ниже предполагают запуск из корня репозитория. Относительный путь, заданный через `SANA_DB`, разрешается относительно текущей рабочей папки.

По умолчанию сервер доступен только на вашем компьютере. Это демонстрационная среда без проверки прав владельцев; для публичного размещения нужны доработки из раздела [Ограничения](#ограничения-и-следующие-шаги).

## Пользовательский сценарий

### 1. Бизнес создаёт задачу

1. Выберите демо-роль **«Бизнес»** в правом верхнем углу.
2. Нажмите **«Создать задачу»**.
3. Укажите направление и описание длиной от 10 символов. Кнопка «Подставить демо-пример» вставляет пример кофейни.
4. Нажмите **«Уточнить задачу»**. Появятся вопросы о недостающих сведениях.
5. Ответьте на вопросы. Неизвестные сведения можно оставить пустыми.
6. Нажмите **«Собрать карточку»**, добавьте название и проверьте все поля.
7. Посмотрите предварительную оценку и рекомендации справа.
8. Подтвердите сведения галочкой и нажмите **«Подтвердить и опубликовать»**.

Кнопка «Сохранить черновик» сохраняет неопубликованную карточку в разделе «Мои задачи». Без подтверждения её рейтинг равен 0. Текст в форме до сохранения хранится только в памяти страницы и может исчезнуть после перезагрузки или перехода на другой экран.

### 2. Студенты отправляют предложение

1. Переключите роль на **«Студент»** и выберите одну из пяти команд.
2. Найдите задачу в каталоге. Можно использовать поиск и фильтры.
3. Откройте карточку и заполните идею, план, срок и ссылку на прототип.
4. Нажмите **«Отправить предложение»**.
5. В «Моих откликах» появится предложение со статусом «На рассмотрении».

Отклик разрешён на любую опубликованную задачу, даже с низким рейтингом. Повторные предложения одной команды допустимы: искусственного лимита нет.

### 3. Бизнес выбирает команду

Переключитесь обратно на «Бизнес», откройте задачу и сравните отклики. Для каждого доступны «Выбрать команду» и «Отклонить». Принятое или отклонённое предложение можно вернуть на рассмотрение.

Можно выбрать одну, несколько или ни одной команды. Система не назначает исполнителей автоматически и не закрывает задачу после первого выбора.

### 4. Команда подтверждает прогресс

Выбранная команда открывает «Мои отклики», указывает название выполненного этапа и ссылку на результат. Бизнес видит этап внутри отклика и нажимает **«Подтвердить +20»**. Баллы появляются в разделе «Команды» и в кабинете команды.

Повторное подтверждение одного этапа не начисляет баллы ещё раз. Новые этапы может отправлять только команда выбранного отклика. Если отклик отклонён или возвращён на рассмотрение, подтверждать его новые этапы нельзя. Ранее начисленные баллы автоматически не отзываются.

## Поля карточки

| Ключ | Название | Что нужно описать |
|---|---|---|
| `title` | Название | Короткая суть задачи, 3–160 символов |
| `context` | Контекст | Как процесс устроен сейчас и где возникает проблема |
| `need` | Потребность | Что необходимо изменить |
| `users` | Пользователи | Для кого создаётся решение |
| `data` | Данные и материалы | Доступные файлы, примеры, источники, объём данных |
| `constraints` | Ограничения | Сроки, технологии, доступы и другие границы |
| `result` | Ожидаемый результат | Что команда должна передать бизнесу |
| `criteria` | Критерии успеха | Как бизнес проверит результат |
| `contact` | Контакт | Рабочий способ связи |
| `interaction` | Формат взаимодействия | Консультации и порядок обратной связи |

Все поля — строки. Кроме названия, допускаются пустые значения и текст до 4000 символов. Пустые поля уменьшают рейтинг, но не запрещают подтверждение и публикацию. Направление `topic` выбирается отдельно: образование, ритейл, экология, логистика или сервисы.

## Рейтинг готовности

### Формула

```text
score = Σ weight(field) × is_filled(field) × is_confirmed
```

`is_filled` и `is_confirmed` принимают 0 или 1. Подтверждение относится ко всей текущей карточке. Частичные баллы внутри отдельного поля не начисляются. Название обязательно, но не участвует в рейтинге.

| Критерий ТЗ | Поля реализации | Максимум |
|---|---|---:|
| Контекст и потребность | `context` — 10, `need` — 10 | 20 |
| Данные и материалы | `data` | 20 |
| Ожидаемый результат | `result` | 15 |
| Критерии успеха | `criteria` | 15 |
| Ограничения | `constraints` | 10 |
| Пользователи | `users` | 10 |
| Связь с бизнесом | `contact` — 5, `interaction` — 5 | 10 |
| **Итого** | | **100** |

Поле считается заполненным, если после удаления крайних пробелов оно содержит минимум 3 символа и не равно одному из значений: `нет`, `не знаю`, `уточним`, `потом`, `неизвестно`, `тест`, `n/a`, `???`, `...`. Проверка этих значений не зависит от регистра.

Это проверка полноты описания. Она не определяет истинность данных, качество идеи или измеримость каждого критерия. Ответственность за подтверждение сведений остаётся у бизнеса.

### Уровни и пример

| Баллы | Уровень |
|---|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Пример: подтверждены только контекст и потребность — **20**. Добавлены данные — **40**. Добавлены результат и критерии — **70**. Заполнены все остальные поля — **100**. Если убрать данные из полной карточки, оценка станет **80** после подтверждения изменений.

В редакторе JavaScript показывает предварительную оценку. Сервер независимо вычисляет итоговый рейтинг из сохранённых полей: передать произвольный `score` в запросе недостаточно, чтобы изменить баллы.

### Публикация и каталог

- Неопубликованные карточки отсутствуют в интерфейсе общего каталога.
- Подтверждённая карточка с 0–39 баллами может быть опубликована и получать отклики. **Уровень «Черновик» не означает «не опубликовано».**
- При обновлении опубликованной карточки требуется повторное подтверждение. До сохранения каталог показывает прежнюю версию.
- Задачи сортируются по убыванию рейтинга. При равном рейтинге более поздняя дата создания идёт раньше; для одинаковых временных меток дополнительный порядок не задан.
- Поиск проверяет название, контекст и потребность без учёта регистра. Фильтры направления и уровня работают совместно с поиском.
- Снятие с публикации и удаление задач в текущем интерфейсе не реализованы.

## AI-функция

Режим называется `local-stub` и явно обозначен в интерфейсе. Его алгоритм:

1. Проверить длину черновика и структуру полей.
2. Перенести исходный черновик в `context`, если контекст ещё пуст.
3. Найти пропуски по тем же правилам заполненности, что использует рейтинг.
4. Выдать вопросы по пропускам. Если пропусков меньше трёх, дополнить список проверочными вопросами.
5. Для ритейла уточнить наличие истории продаж; для образования — группы пользователей.
6. Проверить структуру результата и вернуть неизменённые исходные поля.

Ответы пользователь вводит сам, после чего интерфейс переносит их в редактор карточки. Заглушка не извлекает все факты из произвольного текста и не обращается к внешней модели.

**Промпт:**

> Ты помогаешь бизнесу уточнить задачу для студентов. Вход: JSON `{draft, topic, fields}`. Только факты пользователя. Не заполняй пропуски догадками. Верни JSON `{mode, questions: [{field, question}], fields}`. Не менее 3 уместных вопросов о пропущенных или неясных полях. `fields` содержит только предоставленные пользователем значения. Пользователь редактирует и подтверждает карточку. Не оценивай и не назначай команды.

`validate_ai_result` отклоняет не-объект, недостаточное количество вопросов, неизвестные поля, некорректный текст вопроса и изменения исходных фактов. API возвращает сообщение об ошибке, интерфейс оставляет форму для исправления и повторной попытки.

Полный пример входа и выхода, ограничения и порядок подключения реальной модели: [AI-CONTRACT.md](docs/AI-CONTRACT.md). В текущей версии нет настройки API-ключа: для внешнего AI потребуется изменить серверный адаптер.

## Архитектура и структура проекта

```text
Браузер: HTML / CSS / JavaScript
             │ fetch, JSON
             ▼
Python: ThreadingHTTPServer
             │ валидация и бизнес-правила
             ▼
SQLite: задачи, команды, отклики, этапы
```

Один Python-процесс обслуживает статические файлы и API на одном адресе. Клиент не требует сборки. Мутации выполняются в транзакциях SQLite под блокировкой `RLock`. SQL-запросы с пользовательскими значениями используют параметры.

```text
ai-sana-hackathon/
├── server.py                 # HTTP API, рейтинг, AI-заглушка, SQLite
├── static/
│   ├── index.html            # Оболочка приложения
│   ├── app.js                # Экраны, формы, запросы и предварительный рейтинг
│   └── style.css             # Стили и адаптивная вёрстка
├── tests/
│   └── test_hub.py           # 11 тестов бизнес-правил
├── docs/
│   ├── AI-CONTRACT.md        # Промпт, JSON-контракт и валидация
│   ├── DEMO.md               # Сценарий защиты до 5 минут
│   ├── TEAM-PLAN.md          # План работы для 3 участников
│   └── AI-Sana-Defense.pptx  # Презентация для защиты
├── data/                     # Создаётся при запуске, исключена из Git
│   └── hub.sqlite3
├── .gitignore
└── README.md
```

### Модель данных

| Таблица | Основные поля | Связи и назначение |
|---|---|---|
| `tasks` | `id`, `topic`, `draft`, `fields`, `confirmed`, `published`, `revision`, `created` | `fields` хранится как JSON-текст; рейтинг вычисляется при чтении |
| `teams` | `id`, `name`, `interests`, `skills`, `technologies` | Профили демонстрационных команд |
| `proposals` | `id`, `task_id`, `team_id`, `idea`, `plan`, `duration`, `link`, `status`, `created` | Ссылается на задачу и команду |
| `milestones` | `id`, `proposal_id`, `name`, `evidence`, `status`, `points`, `created` | Ссылается на отклик; хранит подтверждение этапа |

Статусы отклика: `pending` → на рассмотрении, `selected` → выбрана, `rejected` → отклонена. Бизнес может менять решение между этими состояниями. Статусы этапа: `pending` и `confirmed`. Баллы команды — сумма `points` её этапов.

При обновлении задачи клиент передаёт `revision`. Если версия уже изменилась, сервер отклоняет сохранение, чтобы устаревшая копия не перезаписала новые данные. Исходный `draft` при редактировании карточки не изменяется.

## Демонстрационные данные

При первом запуске новой базы создаются пять подтверждённых опубликованных задач. Исходные черновики хранятся в поле `draft` тех же записей.

| ID | Задача | Баллы | Уровень |
|---|---|---:|---|
| `t1` | Прогноз спроса для небольшой кофейни | 100 | Приоритетная |
| `t2` | Навигатор по университетским возможностям | 85 | Готовая |
| `t3` | Карта раздельного сбора отходов | 65 | Рабочая |
| `t4` | Планирование маршрутов доставки | 30 | Черновик |
| `t5` | Помощник для службы поддержки | 10 | Черновик |

Команды: `u1` — Nomad Labs, `u2` — Qadam, `u3` — Green Step, `u4` — Route Makers, `u5` — Sana Studio. Есть пять исходных откликов `p1`–`p5`, все на рассмотрении. Этапов при первом запуске нет.

Данные синтетические. Контакты и ссылки `example.com` — примеры. Упоминания CSV и других материалов в карточках демонстрируют описание задачи: сами датасеты и рабочие прототипы команд в комплект не входят.

## API

Базовый адрес: `http://127.0.0.1:8765`. Тела POST-запросов — JSON-объекты в UTF-8. Успешные ответы возвращают HTTP 200. Поле `role` — переключатель демо-сценария, а не аутентификация.

| Метод и путь | Вход | Успешный ответ |
|---|---|---|
| GET `/api/state` | Нет | `tasks`, `teams`, `proposals`, `milestones`, `topics`, `labels`, `rubric`, `aiPrompt` |
| POST `/api/ai` | `draft`, `topic`, `fields` | `mode`, `questions`, `fields` |
| POST `/api/tasks` | `role: business`, `topic`, `fields`, `confirmed`, `published`; при обновлении `id`, `revision` | Карточка с `score`, `level`, `breakdown`, `missing` |
| POST `/api/proposals` | `role: student`, `task_id`, `team_id`, `idea`, `plan`, `duration`, `link` | `{"id":"…"}` |
| POST `/api/decision` | `role: business`, `id` отклика, `status` | `{"ok":true}` |
| POST `/api/milestones` | `role: student`, `proposal_id`, `team_id`, `name`, `evidence` | `{"id":"…"}` |
| POST `/api/milestones/confirm` | `role: business`, `id` этапа | `{"ok":true}` |

`GET /api/state` возвращает в том числе неопубликованные карточки. Их скрывает фильтр каталога на клиенте; это не механизм приватности.

### Пример: уточняющие вопросы

В macOS/Linux при запущенном сервере:

```bash
curl -s http://127.0.0.1:8765/api/ai \
  -H 'Content-Type: application/json' \
  -d '{"draft":"У кофейни остаётся выпечка. Хотим точнее планировать закупки.","topic":"Ритейл","fields":{}}'
```

Ответ содержит `mode: "local-stub"`, минимум три вопроса и все поля карточки. `context` содержит исходный черновик, остальные неизвестные поля остаются пустыми.

### Пример: публикация слабой задачи

Следующий запрос **создаёт запись в текущей локальной базе**. Сохраните возвращённый `id`, если хотите затем обновлять эту карточку.

```bash
curl -s http://127.0.0.1:8765/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{
    "role":"business",
    "topic":"Ритейл",
    "draft":"Нужно лучше планировать закупки выпечки.",
    "fields":{
      "title":"План закупок кофейни",
      "context":"К вечеру остаётся непроданная выпечка.",
      "need":"Сократить списания."
    },
    "confirmed":true,
    "published":true
  }'
```

Ожидается `score: 20`, `level: "Черновик"`, `confirmed: true`, `published: 1`, `revision: 1`. Карточка появится в каталоге и будет доступна для откликов.

**Обновление не является частичным PATCH.** Передавайте все актуальные поля `fields`, а также `id` и текущую `revision`: отсутствующие поля будут заменены пустыми строками. После успешного сохранения версия увеличивается на 1. Используйте настоящие JSON-значения `true`/`false`, а не строки.

### Ошибки и валидация

| Условие | Ответ |
|---|---|
| Неподходящие поля, короткий текст, неизвестная команда, конфликт версии | HTTP 400, `{"error":"Описание ошибки"}` |
| Публикация без подтверждения | HTTP 400 |
| Отклик на неопубликованную задачу | HTTP 400 |
| Этап от невыбранной или другой команды | HTTP 400 |
| Присутствующий `Origin` не совпадает по хосту и порту с `Host` | HTTP 403 |
| Неизвестный GET-путь | HTTP 404 |
| Неожиданная ошибка обработки POST | HTTP 500 с общим сообщением |

Максимальный размер тела POST — 100 000 байт. Название этапа ограничено 200 символами. Для отклика идея, план, срок и ссылка обязательны, минимум по 3 символа. Ссылки должны использовать `http` или `https`, содержать hostname и не включать логин/пароль. Доступность адреса и содержимое прототипа сервер не проверяет.

## Тестирование

Из корня проекта:

```bash
python3 -m unittest discover -s tests -v
```

Windows:

```powershell
py -m unittest discover -s tests -v
```

Ожидаемый итог: `Ran 11 tests` и `OK`. Тесты создают отдельную временную SQLite-базу и не изменяют рабочие данные. Запуск HTTP-сервера для них не требуется.

Проверяются:

- минимальный объём исходных данных и ожидаемые рейтинги;
- сумма весов, подтверждение и границы уровней;
- публикация только после подтверждения;
- отклики на слабые задачи и запрет откликов на неопубликованные;
- выбор нескольких команд, принадлежность этапа и однократность начисления;
- конфликт версий и пересчёт после редактирования;
- вопросы AI, сохранение исходного текста и отклонение повреждённого ответа;
- обязательные поля, роли, ссылки и сохранение записей.

Эти тесты проверяют бизнес-логику напрямую. Они не заменяют проверку браузера, HTTP-транспорта и публичной безопасности. Полный путь был дополнительно проверен вручную в локальном браузере.

### Ручная приёмка

| Действие | Ожидаемый результат |
|---|---|
| Открыть чистую базу | 5 задач с баллами 100, 85, 65, 30, 10 |
| Создать черновик и запросить уточнение | Не менее 3 вопросов, без выдуманных данных |
| Собрать карточку и убрать поле данных из полной задачи | Предварительная оценка меняется со 100 на 80 |
| Опубликовать без галочки | Сообщение о подтверждении; текст формы сохраняется |
| Подтвердить и опубликовать | Карточка появляется в каталоге по рейтингу |
| Выбрать фильтр «Черновик» | Слабые опубликованные задачи остаются видны |
| Отправить отклик студентом | Статус «На рассмотрении» в кабинете команды |
| Выбрать команду бизнесом | Статус «Выбрана», доступна отправка этапа |
| Подтвердить этап | +20 баллов команде, повторного начисления нет |
| Обновить страницу | Сохранённые карточки, решения и баллы остаются |

Подробный сценарий с готовыми текстами: [DEMO.md](docs/DEMO.md).

## Хранение данных и чистая репетиция

Данные находятся в `data/hub.sqlite3`, которая создаётся автоматически и исключена из Git. Повторный запуск использует существующую базу, а не сбрасывает её. Демо-данные добавляются при инициализации новой базы. В браузерном `localStorage` хранятся только выбранная роль и команда.

Чтобы начать отдельную репетицию и сохранить прежние результаты, задайте **новый** путь к базе:

```bash
SANA_DB=data/rehearsal-01.sqlite3 python3 server.py --port 8766
```

PowerShell:

```powershell
$env:SANA_DB = "data/rehearsal-01.sqlite3"
py server.py --port 8766
```

При повторном использовании того же пути репетиция продолжится с сохранёнными данными. Для следующего чистого прогона выберите другое имя файла. В PowerShell переменная сохраняется в текущем окне терминала; после остановки сервера вернуть путь по умолчанию можно командой `Remove-Item Env:SANA_DB`.

Для резервной копии остановите сервер и скопируйте SQLite-файл в отдельную папку. API удаления и восстановления данных в MVP нет. Не добавляйте рабочую базу с реальными сведениями в Git.

## Частые проблемы

| Симптом | Что сделать |
|---|---|
| `python3` или `py` не найдена | Установить Python 3.10+ и проверить командой `python3 --version`, `py --version` или `python --version` |
| `can't open file server.py` | Перейти в папку с `server.py`, а не в её родительскую папку |
| `Address already in use` | Уже занят порт 8765; выбрать `--port 8766` и открыть соответствующий адрес |
| Браузер не подключается | Убедиться, что процесс Python работает и адрес совпадает с выводом терминала |
| Интерфейс открыт через `file://` | Запустить Python-сервер и открыть HTTP-адрес |
| Нет новых стилей после изменения кода | Выполнить жёсткое обновление страницы; горячая перезагрузка не реализована |
| Карточка не появляется в каталоге | Проверить, что она подтверждена и опубликована; сбросить поиск и фильтры |
| Публикация требует подтверждения повторно | После изменения полей нужно снова поставить галочку |
| Ошибка «Карточка уже изменилась» | Скопировать несохранённый текст, обновить страницу, открыть актуальную карточку и повторить правки |
| Изменения другого участника не видны | Обновить страницу; автоматических обновлений между браузерами нет |
| Баллы команды равны 0 | Проверить выбор команды и подтверждение конкретного этапа бизнесом |
| `database is locked` | Убедиться, что несколько серверов или SQLite-редактор не удерживают одну базу; использовать отдельный `SANA_DB` |
| `PermissionError` при запуске | Проверить права на папку данных и разрешение среды открывать локальный порт |

## Команда из 3 человек

| Роль | Ответственность | Участие в защите |
|---|---|---|
| A — интерфейс | `static/`, конструктор, каталог, кабинеты | Управляет браузером и показывает переходы |
| B — сервер и данные | SQLite, API, рейтинг, отклики, этапы | Объясняет формулу, хранение и ручные решения |
| C — AI и качество | AI-контракт, вопросы, тесты, документация | Объясняет проблему, режим AI и ограничения |

B и C заранее согласуют границы изменений в `server.py`: C отвечает за `AI_PROMPT`, `QUESTIONS`, `ai_questions`, `validate_ai_result`, B — за остальные функции.

План на пять часов и контрольные точки: [TEAM-PLAN.md](docs/TEAM-PLAN.md). Имена участников можно добавить после распределения ролей.

## Ограничения и следующие шаги

Текущий MVP рассчитан на локальный показ с синтетическими данными:

- Нет регистрации, сессий и прав владельцев. Любой пользователь демо-пространства может переключить роль; API отдаёт все карточки и отклики.
- Нет внешней языковой модели, семантической оценки качества описания и автоматических рекомендаций задач.
- Нет загрузки файлов, чата, уведомлений, восстановления пароля, редактирования профилей команд и удаления записей.
- Нет проверки реального содержимого результатов по ссылкам. За подтверждение этапа отвечает бизнес.
- Нет автоматической синхронизации интерфейсов, пагинации, миграций БД, аудита решений и ограничения частоты запросов.
- Рейтинг реагирует на наличие текста, поэтому сам по себе не защищает от бессодержательного заполнения.

В коде есть экранирование пользовательского текста, параметризованные SQL-запросы, проверка схемы ссылок, ограничения размера запроса и проверка присутствующего Origin. Это базовая валидация для MVP, не замена авторизации или проверке безопасности перед публичным запуском.

Предлагаемый порядок развития: сначала авторизация и права доступа, затем модель для формулирования вопросов с проверкой JSON и таймаутами, после этого более глубокая проверка описания, аудит и инфраструктура. Автоматический выбор исполнителей не планируется: решение остаётся у бизнеса.
