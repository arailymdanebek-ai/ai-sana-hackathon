# AI Sana Challenge Hub

Работающий MVP для кейса МНВО — AI Sana. Бизнес превращает короткий черновик в подтверждённую карточку, видит рейтинг готовности и публикует её в общем каталоге. Студенты отправляют предложения, бизнес вручную выбирает команды и подтверждает выполненные этапы.

## Быстрый запуск

Требуется Python 3.10 или новее. Установка пакетов, Node.js и API-ключ не нужны.

1. Распакуйте архив и откройте терминал в папке `ai-sana-hub`.
2. Выполните `python3 server.py` (Windows: `py server.py`).
3. Откройте http://127.0.0.1:8765 в браузере.
4. Оставьте терминал открытым. Остановка: Ctrl+C.

Другой порт: `python3 server.py --port 8766`.

Сервер по умолчанию доступен только на текущем компьютере. В приложении нет настоящей авторизации, поэтому этот MVP предназначен для локальной демонстрации на синтетических данных.

## Что реализовано

- Свободный ввод черновика и уточняющие вопросы по пропускам, минимум три.
- Редактируемые поля: название, контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт и формат взаимодействия.
- Ручное подтверждение перед публикацией и после редактирования опубликованной карточки.
- Серверный рейтинг от 0 до 100, расшифровка, недостающие поля и предварительная оценка в редакторе.
- Общий каталог, сортировка по рейтингу, поиск, фильтры по теме и уровню готовности.
- Неограниченные отклики, включая отклики на задачи с низким рейтингом.
- Идея, план, срок и ссылка на прототип в каждом отклике.
- Ручной выбор одной или нескольких команд, отклонение, возврат на рассмотрение.
- Отправка этапа выбранной командой и подтверждение бизнесом: +20 баллов за этап. Повторное подтверждение не удваивает баллы.
- Переключение демо-ролей и пяти команд, сохранение данных в SQLite.
- Пять синтетических черновиков с карточками разной полноты, пять профилей и пять откликов при первом запуске.

## Архитектура

`static/index.html` — оболочка приложения. `static/app.js` — интерфейс и состояние текущего экрана. `static/style.css` — адаптивная вёрстка. `server.py` — HTTP API, валидация, локальная AI-заглушка, рейтинг и SQLite. `tests/test_hub.py` — проверки бизнес-правил.

Таблицы: `tasks` (черновик, поля карточки, подтверждение, публикация, версия), `teams` (интересы, навыки, технологии), `proposals` (отклик и решение), `milestones` (результат этапа, подтверждение, баллы).

Клиент обращается к API того же сервера. Баллы и переходы состояния проверяются на сервере. `revision` предотвращает перезапись карточки устаревшей копией. Данные не исчезают после перезагрузки страницы или перезапуска Python.

## Формула рейтинга

Рейтинг = сумма весов заполненных и подтверждённых полей. Название обязательно для сохранения, но не даёт баллы.

| Поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| **Всего** | **100** |

Поле считается заполненным, если после удаления крайних пробелов осталось хотя бы 3 символа и значение не равно «нет», «не знаю», «уточним», «потом», «неизвестно», «тест», `n/a`, `???` или `...`. Это прозрачная проверка полноты, а не автоматическая оценка смысла. Достоверность и достаточность содержания подтверждает бизнес. Неподтверждённый черновик имеет 0 баллов. В редакторе показывается отдельно обозначенная предварительная оценка.

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. После подтверждённого изменения сервер заново вычисляет рейтинг. Сортировка идёт по убыванию рейтинга, при равенстве сохраняется порядок по дате создания (новые раньше).

Важно: уровень «Черновик» и статус «Не опубликовано» различаются. Подтверждённую карточку даже с 0 баллов можно опубликовать; она видна всем и принимает отклики. Несохранённые или неопубликованные карточки отсутствуют в каталоге.

## AI-функция и ограничения

Текущая версия использует **локальную заглушку**, разрешённую техническим заданием. Внешняя языковая модель не подключена. Заглушка проверяет пустые поля, задаёт связанные с ними вопросы, адаптирует отдельные вопросы к образованию и ритейлу и дословно переносит ответы в карточку. Она не извлекает все факты из произвольного текста: исходный черновик попадает в поле контекста, остальные сведения пользователь уточняет сам.

Полный промпт, вход, выход, обработка ошибок и точка подключения модели: `docs/AI-CONTRACT.md`. Промпт доступен также в интерфейсе. Нет выдуманных сведений и автоматического выбора исполнителей.

В MVP нет регистрации, проверки принадлежности задач пользователям, реального AI API, загрузки файлов, чата, уведомлений и проверки содержимого внешних прототипов. Поле `role` проверяет сценарий демонстрации и не является защитой доступа. Каталог и карточки находятся в общей демо-базе. Изменения другого браузера видны после обновления страницы. Ссылки `example.com` и контакты в исходных данных являются примерами.

## API

| Метод и путь | Назначение |
|---|---|
| GET `/api/state` | Карточки, команды, отклики, этапы и правила |
| POST `/api/ai` | Уточняющие вопросы и перенос исходных полей |
| POST `/api/tasks` | Создание или подтверждённое обновление карточки |
| POST `/api/proposals` | Отклик команды на опубликованную задачу |
| POST `/api/decision` | Ручное решение бизнеса |
| POST `/api/milestones` | Результат этапа выбранной команды |
| POST `/api/milestones/confirm` | Подтверждение этапа и 20 баллов |

Ошибки ввода возвращают HTTP 400 с JSON `{"error":"…"}`. Клиент показывает сообщение, сохраняет текущую форму и позволяет исправить ввод. Проверяются длины текстов, обязательные поля и схема http(s) для ссылок. Пользовательский текст экранируется перед выводом. Внешние запросы с несовпадающим Origin отклоняются. Статический сервер выдаёт только три явно разрешённых файла.

## Проверки

Из корня проекта: `python3 -m unittest discover -s tests -v`.

11 тестов проверяют минимальный объём данных, границы уровней, подтверждение, доступность слабых задач, запрет откликов на неопубликованные задачи, множественный ручной выбор, начисление этапов, версии карточек, AI-контракт, ошибки ввода и сохранение данных.

Ручной сценарий проверки и защиты: `docs/DEMO.md`. План для **трёх человек** на пять часов: `docs/TEAM-PLAN.md`.

## Чистая репетиция без удаления данных

База создаётся в `data/hub.sqlite3`. Для отдельной репетиции используйте новый путь:

macOS / Linux: `SANA_DB=data/rehearsal.sqlite3 python3 server.py --port 8766`

PowerShell: `$env:SANA_DB="data/rehearsal.sqlite3"; py server.py --port 8766`

Первый запуск автоматически заполнит новую базу. Исходная база останется без изменений. В архиве для сдачи рабочая база не включена, поэтому каждый новый запуск начинается с пяти исходных задач.
